# v1.1 quality review

This review covers the new EmptyState component, representative accessibility
scenarios, and initial loading of the production documentation build.

## Changes

- Added `SEmptyState` with optional icon, title, description, additional content,
  and action slots. It supports the existing theme registry and instance `ui`
  overrides, without assigning a heading level or live-region role.
- Labelled Select triggers as comboboxes and preserved the FormField label instead
  of the primitive's generic popup label.
- Separated option-list semantics from search fields, empty messages, and footer
  actions. Filtering clears `aria-activedescendant` references to removed options
  while preserving valid keyboard highlighting.
- Normalized documentation content lookup and cache keys for trailing-slash URLs
  in both the docs layer and the website override. The same path is used for
  reading-order navigation and repository actions.

The trailing-slash issue was found during browser inspection: server-rendered
content could be replaced by a handled 404 during hydration. The layer now has
installed-consumer coverage for both server rendering and completed hydration at
such URLs. The generated website was also checked directly.

## Validation

- Lint and root/docs type checks passed.
- 1,551 tests passed across 128 files.
- 33 browser checks passed, including five axe/keyboard scenarios. These cover
  light/dark appearance, validation descriptions, navigation, nested-dialog focus
  and Escape handling, adaptive selection, unmatched searches, and related
  Select/Autocomplete/Listbox/TransferList regressions.
- The full packed-consumer suite passed, including generated types, SSR, browser
  interactions, custom themes, and prefixed/default docs-layer consumers.
- Delivered CSS remained within the unchanged budgets: 149,850 bytes / 20,081 gzip
  for the prefixed consumer, and 153,935 bytes / 21,454 gzip for the normal consumer.
- Static generation produced 555 routes. SEO checks verified 128 pages, their
  sharing images, and robots.txt.
- The generated EmptyState page was checked at desktop and phone widths. Its
  table action restores focus after adding a row; clearing the search restores
  Listbox options; switching to dark mode works without hydration errors.

Automated accessibility checks cover representative configurations. They do not
establish conformance for every component combination or consumer theme.

## Loading observations

Measured on 20 October 2026 using a local gzip-compressed static build, a fresh
browser context for each page, 150 ms simulated network latency, a 1.6 Mbps download
limit, and a 4× CPU slowdown. Viewports were 1440×900 and 390×900. These are single
lab samples, not field metrics or guarantees; they do not model DNS, TLS, or CDN
behavior. LCP was recorded shortly after the theme control became interactive.

| Width | Page | First contentful paint | LCP | Theme toggle ready | Layout shift |
| --- | --- | --- | --- | --- | --- |
| 1440 px | `/` | 1048 ms | 1048 ms | 4242 ms | 0.0075 |
| 1440 px | `/components/elements/button/` | 980 ms | 1148 ms | 4934 ms | 0.0010 |
| 1440 px | `/components/data/empty-state/` | 1052 ms | 1052 ms | 5273 ms | 0.0015 |
| 390 px | `/` | 1052 ms | 1052 ms | 4277 ms | 0.0004 |
| 390 px | `/components/elements/button/` | 996 ms | 1172 ms | 4898 ms | 0.0003 |
| 390 px | `/components/data/empty-state/` | 1016 ms | 1016 ms | 5185 ms | 0.0040 |

All six requests retained the requested page after hydration and produced no
browser exceptions. The initial page content appeared around one second, while
shell interaction still took roughly four to five seconds under these conditions.

An offscreen-example hydration experiment did not establish a useful improvement
and was discarded. The hydration safety guard remains in place. Further loading
work should profile the initial module graph and shell readiness separately from
page examples, while preserving SSR content and testing saved/system appearances.
